# 비정형 이벤트 시그널 조사: 검증 가능한 가설부터

검토일: **2026-10-23 UTC**. 대상: 개인용 파랑새 퀀트 리서처 및 담당 개발자.

**문서 상태: 조사·설계만 완료. 데이터 수집기, 전략, 거래, 계정·구독은 구현·개설하지 않았다.** 아래 POC는 개발자 검토용이며 자동매매 승인이나 기대수익 보장이 아니다. 커뮤니티 목록은 별도 문서에서 관리한다.

## 1. 결론 세 가지

1. **의외성보다 관측 시점과 경제적 연결이 중요하다.** 거래소 장애, 거버넌스 변경, 강 수위처럼 “무엇이 언제 공개되었고 무엇에 영향을 줄 수 있는가”를 정의할 수 있는 자료를 먼저 시험한다. 가격 방향뿐 아니라 유동성 악화·변동성·운임 예측도 유효한 연구 목표다.
2. **펜타곤 피자 지수는 흥미로운 사례이지 검증된 매매 시그널이 아니다.** Google 자료는 주문량·배달 목적지가 아니라 동의한 이용자의 익명·집계 방문 혼잡도다. 독립된 전향적/OOS 거래 성과는 이번 조사에서 찾지 못했다. 군사활동의 구체적 실시간 추론은 연구 범위에서 제외한다.
3. **가장 큰 함정은 ‘과거에 발생한 시각’을 ‘내가 알 수 있었던 시각’으로 쓰는 것.** 수정된 토큰 일정, 사후 장애 보고서, 예보 재분석, 익일 공개되는 시간별 전력 자료를 당시 알았던 것처럼 사용하면 허구의 알파가 생긴다.

## 2. 근거 등급과 우선순위

- **D(데이터 확인):** 공식 공급자의 설명·스키마·접근 경로를 확인했다. 수익성이 확인되었다는 뜻이 아니다.
- **M(메커니즘/실증):** 물리적 메커니즘 또는 관측·사건연구 근거가 있다. 거래비용 차감 OOS 알파와 다르다.
- **O(거래 OOS):** 당시 이용 가능 데이터, 사전 고정 규칙, 미관측 기간, 비용을 갖춘 반복 가능한 거래 검증. **아래 후보 중 이번 조사로 O를 부여한 것은 없다.**
- 순위는 개인 연구의 **검증 가능성·접근성·활용성**에 대한 판단이지 수익률 예상 순위가 아니다. 빠른 신호도 시간당 리서처만으로는 저지연 거래 신호가 되지 않는다.

|---|---|---|---|---|

## 3. 후보별 데이터 계약과 반증 포인트

아래의 `시차`는 **검증할 예측 지평** 또는 공식 공개 주기이며, 입증된 선행성이라는 뜻이 아니다. 모든 후보에는 4절의 공통 룩어헤드·다중검정·생존편향·비용 규칙을 적용한다.

### 1) 거래소·서비스 장애 최초 공지

2026-10-25 보완: [장애 자료의 출처/PIT 계약](outage-source-boundaries.md)을 함께 읽는다. 아래 초기 검토 범위는 유지하며, 새 검증이나 collector 구현 완료로 해석하지 않는다.

- **원천:** [Coinbase Status API](https://status.coinbase.com/api), [Kraken Status API](https://status.kraken.com/api). 실제 [Kraken incidents JSON](https://status.kraken.com/api/v2/incidents.json)을 열어 `created_at`, `started_at`, `updated_at`, 개별 업데이트와 영향 컴포넌트가 있음을 확인했다. Coinbase JSON은 이번 브라우징 도구에서 직접 열리지 않아 문서 확인 수준이다.
- **가설 → 자산:** 매칭/API 장애, 입금 지연, 출금 지연을 분리한다. 영향을 받는 자산·거래소의 스프레드/가격괴리·거래량·향후 변동성이 정상 상태와 다를 수 있다. 출금장애가 곧 시장 전체 하락이라는 가정은 하지 않는다.
- **시차·역사:** 최초 공개 이후 5–60분, 보조 4시간. 실제 장애 발생 후 공지가 늦을 수 있다. 문서상 “all incidents”는 **최근 50건**이지 전체 역사 보장이 아니다. 장애별 원문 업데이트를 축적해야 한다. 문서 속 2014년 예시 응답을 현재 장애로 해석하지 않는다.
- **비용·접근:** 공개 상태 API/RSS. 과도한 폴링 금지. 가격·호가 데이터 라이선스는 별도다. [Coinbase 시장데이터 약관](https://www.coinbase.com/legal/market_data)은 개인/내부 연구 이용과 외부 재배포를 구분하므로 원시값·파생 차트를 공개 저장소에 올리지 않는다.
- **혼란변수/조작:** 큰 가격변동이 트래픽 폭주와 장애를 먼저 일으키는 역인과, 공지 지연, UI 오류와 매칭엔진 오류 혼동, 동일 장애 중복 뉴스.
- **검증:** 사전 변동성·수익률·시간대가 비슷한 대조군, 같은 사고는 한 클러스터. 예정 점검/표시 오류는 분리. 비용 검증에는 당시 거래 가능한 다른 시장의 호가·수수료·이체 불가를 반영한다. 캔들만 있으면 체결 가능성은 미검증으로 남긴다.
- **실증 경계:** [Mt. Gox 장애/DDoS 사건연구](https://academic.oup.com/cybersecurity/article/3/2/137/4831474)는 거래활동 영향의 연구 근거이지 현재 API 공지 이후 수익이 남는다는 검증이 아니다.

### 2) 거버넌스: 제안 → 투표 → 대기 → 실행

- **원천:** [Snapshot GraphQL API](https://docs.snapshot.box/tools/graphql-api), [Uniswap 거버넌스 설명](https://developers.uniswap.org/docs/ecosystem/governance/glossary), [공개 포럼](https://gov.uniswap.org/). Snapshot 문서는 기본 60 requests/min 및 메시지 재생을 위한 순서 필드를 설명한다. 새 Governor/Snapshot X 경로는 [공식 안내](https://blog.snapshot.box/snapshot-is-now-home-for-governor-daos)를 별도 확인해야 한다.
- **가설 → 자산:** 수수료 귀속, 소각, 공급, 담보·위험 매개변수 변경의 **처음 공개된 새로운 내용**이 해당 토큰/연관 프로토콜에 영향을 줄 수 있다. 제목의 찬반 감성보다 실제 경제적 변경을 구조화한다.
- **시차·역사:** 첫 포럼 공개 후 수시간–수일; 투표·실행은 이미 예상되었을 수 있다. 제안 생성/수정/투표/온체인 실행 시각을 분리. 포럼 수정 내역과 삭제자료는 완전하지 않을 수 있다.
- **비용·접근:** 공개 API·포럼·체인 로그로 소수 프로토콜부터 가능. 높은 호출량/장기 RPC 조회는 별도 비용 가능. 공개 표결 총계만 사용하며 개인 유권자/지갑 추적은 제외한다.
- **혼란변수/조작:** 장식적 제안, 실행 불가능한 제안, 포럼 스팸, 사전 홍보, 이미 확정된 표결, 체인·계약 버전 변경.
- **검증:** 가격을 가린 상태에서 변경 유형·신규성 라벨링. 실패·철회·무효 제안도 모집단에 포함. 최초 제안, 통과, 실행을 독립 표본처럼 세지 않는다. BTC/ETH·섹터 통제 후 24시간을 주 지평으로 고정하고, 토큰 유동성·대차/펀딩·DEX 비용까지 반영한다.

### 3) Lido 등 프로토콜 전체 인출 대기열

- **원천:** [Lido WithdrawalQueueERC721](https://docs.lido.fi/contracts/withdrawal-queue-erc721/), [읽기 전용 API](https://docs.lido.fi/integrations/api/).
- **가설 → 자산:** 순신규 인출요청/유동성 버퍼/정산 속도 변화가 stETH–ETH 할인율 또는 유동성 위험을 설명할 수 있다. 요청 수보다 **합계 금액·미정산 잔고·대기시간 분포**를 쓴다.
- **시차·역사:** 블록 공개 및 확정성 확보 후 시간–일. 계약 이벤트·요청 생성 timestamp가 있어 역사가 재구성 가능하지만 배포·업그레이드별 커버리지를 확인해야 한다. 과거 시점의 대기시간을 현재 API 추정치로 대체하지 않는다.
- **비용·접근:** 공개 로그/읽기 전용 endpoint. 대량 역사 조회는 RPC 요금·쿼리 제한 가능. 주소는 집계 후 분석 입력에서 제거한다.
- **혼란변수/조작:** 할인율이 먼저 벌어져 상환 차익거래가 생기는 역인과, 큰 요청을 여러 개로 나누는 구조, 버퍼 유입, 네트워크 출구 대기, 프로토콜 변경.
- **검증:** 할인율·기존 대기열을 포함한 기준모형보다 다음 날 스트레스 예측이 개선되는지 확인. 정상기간 전체 포함. ETH 방향 베팅과 구분하며 가스, DEX 가격충격, 이자 기회비용, 헤지 비용을 계산한다.

### 4) 토큰 언락: 예정된 날짜보다 ‘당시 일정의 변화’

- **원천:** [Tokenomist 방법론](https://docs.unlocks.app/miscellaneous/tokenomist-methodologies), [요금표](https://tokenomist.ai/pricing), 각 프로젝트의 최초 공개 문서/vesting contract.
- **가설 → 자산:** 예상보다 커지거나 앞당겨진 공개 언락, 실제 공개 청구가능량 변화가 해당 토큰의 공급 부담·변동성에 영향을 줄 수 있다. 언락은 실제 매도와 같지 않다.
- **시차·역사:** 날짜는 몇 달 전부터 알려질 수 있고 월/주 단위 추정도 있다. 공급자 방법론상 일부 블록 기반 시간은 4시간마다 갱신. **현재 일정표로 과거를 채우면 룩어헤드**다. 최초 공개 시점·일정 revision을 보존한다.
- **비용·접근/출처:** 무료 기능은 제한적. 검토 시 Pro 화면은 월 환산 $69, 연 $828와 API 1,000회/월을 표시했으나 결제주기·프로모션에 따라 변하므로 구매 전 재확인. 우선 공개 프로젝트 자료/온체인 검증/vesting contract만 허용한다. 공급자의 `Private Project Data` 및 불명확한 출처는 개인 연구에서도 제외한다.
- **혼란변수/조작:** 사전 헤지, OTC, 공급 정의 변경, 거래소 상장, 토큰 수명주기, 반복 언락의 중첩, 현재 생존 토큰만 고르는 오류.
- **검증:** 모든 당시 상장·거래가능 토큰을 as-of로 구성하고 상폐 포함. 날짜·크기를 고정한 계획 대비 수정량을 시험; 같은 토큰/월을 클러스터링. 숏 가능성·펀딩·대차 비용으로 순성과 재평가.
- **실증 경계:** [Keyrock 원문](https://keyrock.com/from-locked-to-liquidity-what-16000-token-unlocks-teach-us/)은 40토큰·16,000여 이벤트와 전후 30일 분석을 제시한다. 공급자 자체의 후향적 사건분석이며, 독립 OOS 또는 실행비용 차감 성과로 인용하지 않는다. ‘90%’를 미래 성공확률로 읽지 않는다.

### 5) 강 수위 → 바지선 운임 → 곡물 물류

- **원천:** [USGS 최신 Water Data API 문서](https://api.waterdata.usgs.gov/docs/), [API 키/호출 정책](https://api.waterdata.usgs.gov/docs/ogcapi/keys/), [USDA 바지선 자료](https://www.ams.usda.gov/services/transportation-analysis/barge), [2025-09-25 운송 보고서](https://www.ams.usda.gov/sites/default/files/media/GTR09252025.pdf).
- **가설 → 자산:** 낮은 수위·급격한 저하 → 적재 제한·운송비 증가 → 곡물 현물 베이시스/수출경쟁력 변화. 상장 운송·곡물 기업과 선물은 **2차 연결**이며 바로 가격 방향을 단정하지 않는다.
- **시차·역사:** 센서 관측부터 일–주, USDA 주간 운임 발표보다 앞선 운임 nowcast가 1차 목표. 센서별 측정/전송 간격·과거 기간·수정 상태가 다르다. 관측 시각과 데이터 공개 시각을 구분한다.
- **비용·접근:** 공공 자료, 제한된 익명 API; 대량/자동 조회는 무료 키 등 운영정책 확인 필요. 신규 키 발급은 이번 범위에서 하지 않았다. 옛 NWIS URL만 하드코딩하지 않는다.
- **혼란변수:** 수확량·수출 주문·연료비·계절성·홍수·준설/수로 제한·철도 대체. 수위 기준점은 지점마다 다르므로 단순 절대높이 비교 금지.
- **검증:** 미리 고정한 상업 수로 구간의 표준화 수위/변화와 운임을 연결; 한 유명 가뭄만 고르지 않는다. 특정 재난 연도를 통째로 빼도 유지되는지 확인. 거래 연결 단계에서는 베이시스/선물 롤·스프레드/기업별 실제 노출을 검증한다.

## 4. 모든 후보에 적용할 검증 규약

### 4.1 공통 이벤트 스키마(제안, 아직 구현하지 않음)

```text
event_id / canonical_incident_or_proposal_id
source_name / source_url / source_type / public_provenance
event_effective_at_utc       # 실제 발생 또는 시행시각
source_published_at_utc      # 공급자가 주장하는 게시시각
first_observed_at_utc        # 연구 시스템이 실제로 처음 본 시각
retrieved_at_utc / revision_id / payload_hash
availability_quality        # observed / archived / asserted_only / unknown
license_checked_at / allowed_use / redistribution_allowed
category / scheduled_flag / affected_asset_ids_asof
universe_snapshot_id / mapping_rationale
aggregate_value / unit / baseline_vintage / missingness
hypothesis_id / label_version / trial_number
```

- 실시간에서 사용 가능한 시점은 검증된 공개시각과 실제 수신시각 이후다. 과거 자료에 현재 `first_observed_at`을 붙였다고 당시 이용 가능성이 복원되는 것은 아니다.
- 과거 공개시각을 확인할 수 없으면 intraday P&L 평가에서 제외하거나 보수적 지연의 별도 민감도 실험으로 표시한다. `unknown`을 0시로 자동 채우지 않는다.
- 최신 결과·최종 제안 본문·사후 장애 원인을 과거 특징으로 join하지 않는다. `as_of` join과 원문 revision을 보존한다.
- 공개 집계만 저장. 개인 이동정보·고용인 추적·개인 지갑 프로파일·비공개 Telegram/insider 자료는 범위 밖이다. 재배포 불가 시장데이터는 저장소에 넣지 않는다.

### 4.2 테스트 설계

1. **사전등록:** 대상 자산·기간·주 지평 1개·특징/방향·기준모형·비용·최소 표본·실패 기준을 먼저 고정한다. 나머지는 탐색으로 표시한다.
2. **시간 분할:** expanding/rolling walk-forward. 중첩 사건·라벨 지평은 purge/embargo하고 같은 사고·프로토콜·토큰의 관련 사건을 다른 fold에 흩뿌리지 않는다. 데이터 탐색 때 이미 본 역사 holdout은 진정한 미관측 미래가 아니므로 마지막에는 전향적 shadow 검증이 필요하다.
3. **다중검정:** 실패한 조합까지 trial ledger에 기록. 12후보×지평×파라미터를 시도한 뒤 최고 Sharpe만 보여주지 않는다. 탐색에 FDR 등 보정, 확정 가설에는 잠근 최종 테스트. [Bailey 등 PBO 원문](https://escholarship.org/uc/item/4w1110bb)은 많은 전략 시도에서 보통 holdout만으로 과적합이 해결되지 않음을 다룬다.
4. **생존·선택편향:** 당시 존재한 종목/토큰/거래소·상폐·실패 프로토콜·철회 제안·평범한 무사건일도 포함. ‘뉴스가 난 사건’만으로 사건집합을 만들지 않는다.
5. **비용/실행:** 수수료 양방향, bid–ask, 시장충격, 펀딩/대차, 가스, 롤, 환전, latency, outage 중 체결불가를 포함. 중간가격 체결을 보장하지 않는다. 기본 비용 및 2배 비용, 관측 지연 확대에서 민감도 보고.
6. **결과 분리:** (a) 데이터가 생기는가, (b) 경제변수를 예측하는가, (c) 가격/위험을 추가 예측하는가, (d) 실제 실행 가능한 순수익이 남는가. 각 단계 통과 여부를 따로 표시한다.
7. **반증:** 시간대/요일 보존 placebo, 이미 알려진 가격움직임 통제, signal lead를 바꿔 사후 반응인지 확인, 유명 사건 하나 제외, 다른 체제/시장 holdout. 신뢰구간은 사건/날짜 클러스터를 고려한다.

## 5. 개발자에게 제안할 저비용 POC 3개

숫자 임계치는 이미 입증된 기준이 아니라 **개발 착수 전 고정할 초기 제안값**이다. 표본/검정력 분석 후 결과를 보기 전에 조정 가능하다. 데이터 구독을 먼저 구매하지 않는다.

### POC A — 장애 알림은 가격이 아니라 ‘남아 있는 유동성 위험’을 알려주는가?

- **최소 범위:** Kraken/Coinbase 공개 상태 공지. 예정 점검, 입금, 출금, 매칭/API, 표시 오류를 분리. BTC/ETH와 사건 시점 사전 유동성 기준을 만족한 영향 자산만 대상; 기존 코드에 맞춰 개발자가 adapter를 결정한다.
- **개발 계약:** revision별 이벤트 저장, 원천 timestamp와 first-seen 분리, 사고 중복 병합, 당시 자산 매핑, poll 실패 로그. 최근 50건 endpoint를 전체 역사로 처리하지 않는 테스트 필수.
- **1차 목표:** 알림 이후 60분의 거래가능 시장 스프레드/호가 깊이 악화를 기존 변동성·최근 수익률·시간대 모형보다 잘 예측하는가. 과거 호가가 없으면 과거는 사건·변동성 탐색까지만, 호가 목표는 승인 후 전향 수집으로 남긴다.
- **비용/지연:** hourly 리서처만 쓸 경우 5분 시그널 주장을 하지 않는다. 개발자의 별도 저지연 수집 승인 전에는 1시간 이상 지평. 실제 시뮬레이션은 장애 시장 체결·즉시 자금이동을 금지한다.
- **기각/보류:** 알림 전에만 효과가 있고 이후 증분효과가 없으면 선행 시그널 기각. 잠근 테스트에서 기준모형 대비 손실 개선이 없거나 클러스터 CI가 0을 포함하면 미검증. 누락·공지지연·표본부족이면 ‘실패 없음’ 대신 불충분. 순수익은 비용 2배와 현실 지연에서 사라지면 거래가설 기각.
- **완료 산출물:** 접근/지연 보고서, as-of 이벤트 표, 사건유형별 base rate, 대조군 결과, 비용 포함/미포함 분리표. 첫 성공 기준은 매매가 아니라 데이터 정합성이다.

### POC B — 경제적 거버넌스 변경의 ‘첫 공개’에는 추가 정보가 남는가?

- **최소 범위:** 유동성이 충분한 3–5개 프로토콜의 공개 포럼·Snapshot·실행 로그. 수수료 귀속/공급/담보 매개변수 3유형으로 제한하고 실적을 보고 프로토콜을 고르지 않는다.
- **개발 계약:** 첫 공개·수정·온도체크·투표·큐·실행의 단일 proposal lineage. 단순 재공지를 새 사건으로 세지 않는다. 최종 통과 여부는 미래 특징이 아니라 결과다.
- **1차 목표:** 공개 후 24시간 시장/섹터 조정 수익 또는 위험변화 중 **하나를 사전 선택**. 사전 보도·사전가격 움직임·유동성으로 구성한 기준모형에 신규 내용이 추가되는지 평가한다.
- **라벨 규칙:** 라벨러에게 후속 가격·최종 결과를 가리고 `novel_economic_change`, `already_known`, `ambiguous`로 분류. 가능하면 독립 라벨 2개·불일치 비율 기록. 실패·철회 포함.
- **기각/보류:** 최초 공개시각을 확인할 수 없는 사건은 intraday 표본 제외. 효과가 통과된 제안만 사후 고를 때만 나타나거나, 토큰/사건 하나를 빼면 사라지거나, 잠근 테스트·비용 2배에서 순효과가 사라지면 거래가설 기각. 텍스트 분류가 불안정하면 규칙 개선 후 **새로운 미래 표본**으로 검증한다.
- **완료 산출물:** 공개 사건 lineage, 고정 라벨 사전, 비용/중복조정 결과, 다음 표본에 사용할 잠긴 가설. 원시 시장데이터는 공개 PR에 포함하지 않는다.

### POC C — 강 수위만으로 다음 주 바지선 운임을 개선 예측할 수 있는가?

- **최소 범위:** 미리 정한 상업 수로 센서 소수와 USDA 주간 운임. 수위 수준/7일 변화/계절 분위수 3특징; 임의의 센서 수백 개 탐색 금지.
- **개발 계약:** 센서 단위·기준점·수정 플래그, 관측시각/수신시각, USDA 보고서 게시일, 동일 구간의 운임 단위, 결측처리를 명시. 기존 프로젝트 수집 계층에서 검토한다.
- **1차 목표:** 다음 주 운임의 MAE를 계절성+직전 운임 기준모형 대비 개선하는가. 수출수요/연료비 자료를 넣은 강한 기준모형에서도 증분효과를 본다. **주식 매수/매도 신호는 이 POC 범위 밖**이다.
- **검증:** 연도 순 walk-forward, 재난/계절 블록 bootstrap, 알려진 가뭄 연도를 통째로 제외. 마지막에는 사전 고정한 전향 기간에서 재검증. 역사 자료의 최종 정정값밖에 없으면 pseudo-real-time이라고 명시한다.
- **기각/보류:** 테스트 MAE 개선이 사전 제안값 5% 미만이거나 불확실성 구간이 개선 0을 포함하면 운영 채택 보류. 효과가 한 재난에만 의존하거나 자료가 목표 운임보다 늦게 게시되면 선행가설 기각. 경제예측에 성공해도 거래 가능한 상품/노출과 비용이 없으면 알파로 승격하지 않는다.
- **완료 산출물:** 공개 접근성/빈티지 점검, 경제변수 nowcast 평가, 원인별 실패 메모. 저렴하게 틀렸음을 확인할 수 있는 실험이 목적이다.

## 6. 파랑새 리서처 → 개발자 전달 규칙

시간당 리서처는 **발견·출처 대조·가설 카드·중복 제거·반증 업데이트**를 담당한다. 분 단위 데이터 수집/주문/운영환경 변경은 별도 승인과 개발자 소유다.

이슈 후보에는 아래를 붙인다:

1. `hypothesis_id`, 한 문장 인과경로, 대상 자산과 대체 가설.
2. 원문 링크, 확인일, 자료/시각/권리의 확인 수준과 막힌 부분.
3. 관측 가능한 최소 입력, 최초 공개/수신시각, 역사 범위·수정 가능성.
4. 기준모형, 잠글 주 지평, 비용·지연, 구체적 기각 기준.
5. 필요한 코드 인터페이스는 계약으로만 제안하고 담당 개발자가 기존 구조에 맞춰 선택.
6. `new evidence`가 없으면 같은 링크를 매시간 새 이슈로 만들지 않음. 스팸/공급자 마케팅/사후 적중담만으로 실행 이슈를 만들지 않음.

**다음 개발 순서 제안:** A의 데이터 시점·수정 계약 → B의 사건 lineage/라벨 → C의 경제 nowcast. 기존 파랑새가 온체인 집계를 이미 갖고 있다면 C 전에 Lido 대기열을 작은 분석 이슈로 바꿀 수 있다. 실제 우선순위는 담당 개발자가 현재 코드·데이터 권한을 확인한 뒤 결정한다.

## 7. 확인하지 못한 것과 범위 제한

- 어떤 후보도 이 문서 작성 중 직접 백테스트하지 않았다. 기대수익·Sharpe·적중률은 산출하지 않았다.
- TSA 현재 원천은 403, Coinbase incidents JSON은 브라우징 접근 불가, PortWatch 동적 방법론 본문/일별 지연·전체 역사 범위는 직접 확정하지 못했다. 차단 우회·계정 생성·결제는 하지 않았다.
- 일부 원 논문/플랫폼의 페이지가 열리지 않는 경우 검색으로 확보된 공식 설명을 넘는 수치 주장을 하지 않았다.
- 최신 법률·접근권의 법률적 판단은 하지 않는다. 공급자 약관·라이선스·API 제한을 구현 전에 다시 확인하고, 개인 연구용 데이터는 기본 비공개로 유지한다.
- 내부자정보, 비공개 개인 추적, 재식별, 군사활동의 구체적 실시간 추론은 연구 범위에 포함하지 않는다.

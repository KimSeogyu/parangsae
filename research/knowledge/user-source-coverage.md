## 블로그 전수 여부를 판단하는 법

- **nomore_bet:** [전체714개 목록](naver-nomore-inventory.md)에 대한 개별 본문·요약 상태를 맞춘다. 표시712/열거714 불일치는 미해결이다. U09는 목록264번과 같은 글이다. [개별 배치](naver-nomore-post-notes/)와 [통합 ledger](naver-nomore-manifest.json)에서 텍스트/매체 상태를 각각 확인한다.
- 이 명세 생성 시 개별 배치에 존재한 unique 글은 **714개**다. 본문 부족·그림 중심도 개별 상태를 남겼으며 매체별 범위는 통합 ledger를 우선한다.
- 매체는44개 글을 선정 점검했고38개에서 실제 매체를 확인했다. 나머지6개는 선정된 공개 매체가 없거나 확인하지 못했다. 다른670개 글의 매체는 미검토다.
- **dnpquant:** 공개웹0건과 제공된 발췌자료175파일을 별도 분모로 둔다. 175개 파일을 모두 확인했으며173개 식별 본문과2개 오류 파일을 구분한다. 결합본·부분 발췌는 [archive coverage](investor-dnpquant/coverage.md)에서 확인한다. 공개 블로그 전체를 확보했다고 표현하지 않는다.

## 접근 불가 및 권리 경계

- 책의 구독/DRM 본문은 읽지 않았다. 공식 공개 미리보기·목차·초록만 요약했으며 정식 접근이 있더라도 책 대체본을 재게시하지 않는다.
- Silverchair 인증·워터마크 URL은 저장하지 않고 DOI·저자 공개본으로 대체했다.
- 연구 범위 밖 입력(U13)은 수집하지 않았고 URL·내용을 보관하지 않는다.
- repo에는 짧은 독자적 해설·출처·검토 상태만 둔다. 원문 전체·이미지·데이터를 반입하려면 항목별 권리를 별도로 확인한다.

## 완료와 복구의 범위

1. 접근 가능한 블로그 모든 unique ID에 읽기/요약/비연구/차단 등 정직한 상태가 있어야 한다. 미읽음을 제목 기반 요약으로 대체하지 않는다.
2. mlfactor19장 본문과 공식 Python 자료15개를 개별 정적 검토했다. 실행·데이터·JS 도표2개·외부 참고문헌 전체는 남은 별도 범위다.
3. 논문 독서와 전표/부록 재현은 다른 작업이다. 재현·거래 가능한 알파 검증을 했다고 표시하지 않는다.
4. 작업환경 초기화로 소실된 산출물은 저장소 객체·기존 작성 기록에서 복구했다. 개별 문구가 남지 않은 항목은 공개 본문을 다시 읽고 재작성했으며 recovery 필드로 표시했다. 재조회가 없었던 항목을 새 독해로 세지 않는다.
5. 접근 불가·권리 제한 때문에 남는 범위는 명시하며 “모든 자료의 모든 내용 완료”라고 말하지 않는다.

## 현재 문서 경로와 이관 범위

이 ledger와 note_file 경로는 `research/knowledge/`를 기준으로 한다. 2026-10-23 이관에서는 기존 검토본의 공개 웹 자료 요약·제공 발췌자료 분석 노트·상대 경로·제한 표시를 획득 경로별로 보존하고 과거 저장소 이슈 연결과 비연구 입력의 개인적 맥락을 제외했다. 이관 자체를 새로운 원문 독서나 독립 재현으로 계산하지 않는다. 원본 업로드·시세·계정·이전 Git 이력은 이 문서 묶음에 포함하지 않는다.
